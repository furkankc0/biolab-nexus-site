For institutions

BioLab Nexus is set up separately for each institution and stays under the institution’s own control. Below are the setup options, how accounts are opened, the licence and how data is protected.

Accounts and roles

Accounts are opened with the institution’s email addresses. A teacher requests an account for a student; once the administrator approves, a one-time link goes to the student’s school email and the student chooses a username and password.

Only addresses on your institution’s domain are accepted. For a visiting researcher from outside, the administrator can make an exception by giving a reason; this is written to the audit log.

Administrator
Manages all accounts and roles, sets up the institution and chooses which sections are open to which role.
Teacher
Runs analyses, experiments and validation; requests and manages student accounts.
Technician
Manages instruments, reference updates and backups; runs analyses and records.
Student
Runs analyses, batch identification, experiments and bookings; sees only their own records.

Licence

BioLab Nexus is used under a written licence agreement for each institution. The licence is a digitally signed file loaded into the program; no internet connection is needed to verify it.

  • If the licence expires, the program runs read-only: records can be viewed, exported and backed up; no data is deleted or locked.
  • The program cannot be switched off remotely and never connects to the internet to check its licence.
  • Reports show which institution’s licence they were produced under.

Data security and personal data

The institution is the data controller for the personal data in the program. When the program runs on our server, we act as data processor, and this is secured by a data processing agreement with the institution.

  • The program never sends institutional data to the developer; update packages are signed and only ever travel towards the institution.
  • Passwords are stored in a form that cannot be reversed (scrypt); sessions and invitation links expire and work only once.
  • Every action is written to a log that cannot be deleted; the personal details of someone who leaves can be erased while their records are kept.
  • The security review document and the IT installation guide are available on request.
